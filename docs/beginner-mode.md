# 初学者学习模式

Project Xray 不只是“面试题生成器”。对正在摸黑学 Java 的人，它更像一个从代码出发的项目教练。

## 适合谁

- 刚做完课程设计，但说不清自己项目怎么运行
- 准备第一次 Java 后端面试
- 简历里写了 Spring Boot / MyBatis / Redis，但怕被追问
- 看得懂语法，但不知道哪些代码值得讲、哪些地方可能出问题
- 不想背通用八股，想从自己的代码里理解知识

## 学习模式输出什么

每道重点题固定包含：

1. **问题**
2. **当前代码截图**
3. **建议修改图**（如果有）
4. **文件:行号证据**
5. **30 秒口述版**
6. **完整解释**
7. **代码调用链**
8. **为什么这样设计**
9. **边界和代价**
10. **追问及完整回答**
11. **需要补的基础**
12. **自测任务**

## 和面试模式的区别

| 内容 | 面试模式 | 学习模式 |
|---|---|---|
| 30 秒答案 | 必须 | 必须 |
| 完整解释 | 需要 | 需要，且更详细 |
| 代码调用链 | 可选 | 必须 |
| 术语解释 | 可选 | 必须 |
| 常见错误 | 可选 | 必须 |
| 改前/改后代码 | 可选 | 推荐 |
| 自测任务 | 重点题需要 | 重点题必须 |
| 篇幅 | 更短 | 更长，但分层 |

## 学习模式示例提问

```text
$project-xray 扫描 D:\idea.shuju\TaskMaster，
输出到 D:\CodexSkills\runs\TaskMaster-learning。

我是正在学 Java 的初学者，请用学习模式：
- 每道题先放代码截图
- 解释代码调用链
- 用初学者能听懂的话解释术语
- 给出改前/改后代码
- 每道重点题给我一个自测任务
```

## 推荐学习顺序

不要从第一道题顺序背。

建议按下面顺序：

1. 先读“项目画像”，确认项目到底由哪些模块组成
2. 再看 3 个 `[重点]` 问题，理解最关键的代码路径
3. 对每个重点问题，自己先回答一次，再看 30 秒版
4. 再看完整解释，补基础概念
5. 打开代码截图对应的文件，自己找到行号
6. 完成自测任务，再重新扫描

## 学习模式的质量标准

一份好的学习版报告应该让你能回答：

- 这个接口从入口到数据库经过了哪些代码？
- 这段代码为什么这样写？
- 如果数据量变大，哪里会先出问题？
- 如果面试官换一种问法，我还能不能回答？
- 我能不能自己改出一个更合理的版本？

如果一份报告只是让你“看起来懂了”，但不能回到代码，那它还不够好。

## 不要这样用

- 不要把完整答案直接背下来
- 不要跳过代码截图
- 不要在没有运行过项目的情况下假装自己做过线上优化
- 不要把建议修改图当成项目原有代码
- 不要编造 QPS、用户量、故障次数

学习模式的目标不是让你背得更快，而是让你下一次看到类似代码时，能自己判断。
