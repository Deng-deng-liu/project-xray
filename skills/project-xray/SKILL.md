# Project Xray / 项目 X 光机

把仓库代码当作唯一事实源，生成“面试官会追问什么”的证据化报告。你的任务不是编面试题，而是解释扫描器已经找到的信号，并把答案写到初学者和初级程序员能直接理解、面试时能直接说出来的程度。

## 核心约束

- 先运行扫描器，再写报告。不要跳过扫描直接根据目录或文件名猜问题。
- 扫描器负责“有没有”，你负责“怎么讲”。不得新增扫描器没有给出的问题事实。
- 每条踩坑、项目细节题、技术深度题和场景设计题都必须引用至少一个 `E###` 证据。
- 每道题都必须给出完整回答，不能只给“回答骨架”或几个关键词。
- 每个 `E###` 都应嵌入对应的代码证据图；图片必须来自 `render_evidence.py` 或用户提供的真实截图，不得凭空描述截图内容。
- 只有 `confidence: verified` 且 `severity: high` 才能称为“高危坑”。`likely` 和 `uncertain` 只能写“待核实风险”。
- 不得编造线上故障、QPS、用户量、响应时间、故障次数、团队决策或业务背景。没有来源的数字只能写成“假设”或“待核实”。
- 不得把“可能的形成路径”写成“当时确实发生过”。需要用户确认时明确写出来。
- 只读扫描。不得执行仓库代码、安装依赖、运行测试或启动服务。
- 密钥、密码和 Token 必须脱敏。报告中只写字段名和 `***REDACTED***`。
- 简历里的技术点如果无法从代码验证，只能标记“待核实”，不能直接判定造假。

## 输入

- 必填：本地仓库路径。
- 可选：目标岗位方向、简历中关于该项目的原始描述、输出目录、深浅主题。

如果仓库路径不存在或没有可读源码，停止并说明原因。不要用空仓库硬生成报告。

## 工作流

> 前置条件：先安装本项目的 CLI（在仓库根目录执行 `python -m pip install -e .`）。如果只想从源码运行，可用 `PYTHONPATH=src python -m project_xray` 代替下面的 `project-xray`。

1. 预检仓库路径，确认不是空目录。
2. 运行扫描器，生成证据包：

```bash
project-xray scan <repo> --out <output>/signals.json
```

3. 生成 IDE 风格代码证据图：

```bash
project-xray render <output>/signals.json --out-dir <output>/assets --theme dark
```

`project-xray render` 依赖 `Pillow` 和 `Pygments`。如果导入失败，先向用户说明缺少依赖，不要静默跳过截图；用户同意后再安装。

4. 从高价值风险中选择 3—5 条，写 `<output>/fixes.json`，为每条给出最小修改后的 `after_snippet`。格式见 [references/fix-cards.md](references/fix-cards.md)。
5. 生成改前/改后代码卡：

```bash
project-xray fixes <output>/signals.json <output>/fixes.json --out-dir <output>/assets --theme dark
```

6. 读取 `signals.json`、`assets/manifest.json`、`assets/fix-manifest.json` 和用户提供的简历描述。必要时只读取构建文件、目录树和证据片段来补充项目画像；不要通读整个仓库后自由发挥。
7. 阅读 [references/evidence-policy.md](references/evidence-policy.md)、[references/fix-cards.md](references/fix-cards.md) 和 [references/report-template.md](references/report-template.md)。
8. 按模板写 Markdown 报告。先写项目画像和证据化风险，再写三档面试题。
9. 每道题和每个风险都要嵌入对应图片，例如：

```markdown
![Q1 代码证据](assets/E004.png)
```

10. 如果生成了 `E###-after.png`，在对应证据图后追加“建议修改”图；没有生成就不要写该图片引用。
11. 如果用户提供了简历描述，增加“简历声明核验”小节，区分“代码可验证 / 未找到证据 / 需要本人确认”。
12. 运行校验器：

```bash
project-xray validate <report.md> <signals.json>
```

13. 校验失败就修正报告，不要通过删掉证据引用或答案段落来绕过校验。重复直到通过。
14. 最后输出固定总结句。X、Y 和优先题号必须根据报告和证据包计算，不能凭感觉写。

## 使用模式

根据用户目标选择模式：

- **面试模式**：用户说“准备面试、预测追问、简历核验”时使用。答案更短，重点放在 30 秒口述版和追问。
- **学习模式**：用户说“带我看懂、我是初学者、课程设计、学习路线”时使用。必须增加代码调用链、术语解释、常见错误、改前/改后代码和自测。
- 用户没有明确说明时，默认使用“学习模式”，但控制重点题数量，避免报告过长。

学习模式不是把答案写长，而是把项目事实、原理、边界和练习连接起来。

## 题目分层

- **重点题 3—5 道**：完整答案，至少 2 个追问，必须包含基础补充和自测。
- **普通题 3—5 道**：完整答案，至少 1 个追问，包含基础补充。
- **延伸题**：只保留问题、证据图和一句提示，不凑完整答案。
- 题目标题必须带层级标记：`[重点]`、`[普通]` 或 `[延伸]`。
- 优先选择能落到具体代码、能被面试官继续追问的点；信号不足时少出题，不要凑数。

## 答案深度

每道面试题固定按以下顺序输出：

- **题目标题后立即放代码证据图**。
- **证据行**：图片之后保留 `[E###] path:line`，方便复核。
- **为什么会问**：连接代码事实和面试官关注点。
- **30 秒口述版**：3—5 句话，第一人称，面试时能直接说。
- **完整解释**：结合具体代码、调用链、设计取舍和边界展开。
- **面试官追问**：重点题至少 2 个，普通题至少 1 个；每个追问都要给完整回答。
- **你需要补的基础**：列出 2—4 个概念或机制。
- **自测**：重点题必须给出一个可执行的代码修改或验证任务。

答案要口语化、可直接说，不要写成论文。先讲项目事实，再讲通用原理，最后讲边界和验证。

## 证据分级

- `verified`：代码或配置直接可见，可作为事实陈述。
- `likely`：信号明确，但需要调用链、DDL、配置或业务确认。
- `uncertain`：只能作为追问线索，不能称为坑。

证据引用格式：

```text
[E004] src/main/java/.../OrderServiceImpl.java:88-93
```

架构级问题使用证据包，并嵌入多张图：

```text
[E002] pom.xml:21 + [E007] config/RedisConfig.java:18 + [E011] OrderService.java:57-66
```

## 代码证据图规则

- 一张图只展示一个 `E###` 证据，避免把无关代码截进来。
- 图中保留文件路径、行号、高亮行、严重度和置信度。
- 多证据题按 `E001`、`E002` 顺序嵌入多张图。
- 图片必须来自 `project-xray render` 生成的已脱敏 `snippet`；不得把真实密码、secret、token 渲染进图。
- 如果用户提供了真实 IDEA 截图，可以放在 `assets/` 并按 `E###.png` 命名；默认仍使用自动生成图。
- 不要求真正打开 IDEA 截图；自动生成的 IDE 风格图是主流程。
- 高价值问题可以用 `project-xray fixes` 生成 `E###-after.png`；改后代码只是建议方案，必须明确标注“建议修改”，不能假装是项目原有代码。

## 报告结构

严格按 [references/report-template.md](references/report-template.md) 输出，至少包含：

1. 面试速览与项目画像
2. 证据化风险与可讲点
3. 三档面试题：项目细节 / 技术深度 / 场景设计
4. 八股映射卡
5. 反问面试官
6. 固定总结句

如果证据不足以支撑某个模块，写“证据不足”，不要凑数。

## 题目生成规则

- 项目细节题：必须指向具体接口、方法、配置或调用点。
- 技术深度题：必须至少有一个项目锚点；代码只能证明“用了什么”，不能证明“为什么选它”，设计动机要写成待确认假设。
- 场景设计题：必须基于现有架构和约束，先写假设，再给改造方向。
- 八股卡固定三句话：项目锚点、原理与边界、追问应对。
- 没有项目证据的通用八股题单独放在“延伸练习”，不能伪装成项目事实题。
- 答案不要只写“可以从 X、Y、Z 回答”，要把 X、Y、Z 展开成完整句子。

## 输出与收尾

默认把报告写到用户指定的输出目录；没有指定时写到当前工作目录的 `project-xray-report.md`。同时保留：

```text
signals.json
assets/
  E001.png
  E002.png
  E001-after.png   # 可选
  manifest.json
  fix-manifest.json # 可选
fixes.json        # 可选，建议修改方案
```

固定结尾：

```text
本次共发现 X 个可讲点，Y 个高危坑，建议优先准备第 N1、N2 题。
```
