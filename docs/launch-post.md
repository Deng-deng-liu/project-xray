## 摘要

一个面向 Java / Spring Boot 的静态扫描 + 代码证据工具。它不直接生成通用面试题，而是先扫描项目、找到具体代码信号，再生成带 `文件:行号`、代码截图、完整答案和追问的项目面试报告。

## 正文草稿

我学 Java 的过程，基本是摸黑走过来的。

最开始做项目的时候，只要能跑起来就很开心。后来准备面试才发现一个很尴尬的问题：

> 项目是我写的，但我说不清它为什么这么写。

比如：

- 为什么这里要加缓存？
- 这个接口为什么会慢？
- 事务为什么放在这一层？
- Redis 挂了会怎么样？
- 面试官顺着这段代码继续问，我还能答吗？

市面上的面试题工具很多，但大部分会给你：

```text
MySQL 索引原理是什么？
Redis 为什么快？
Spring 事务的传播机制？
```

这些问题不是没用，但它们和我的项目没有关系。面试官真正会问的，往往是：

```text
你项目里这个循环为什么逐条查库？
你这里 catch 住异常之后，调用方怎么知道失败了？
你说用了 Redis，为什么不用本地缓存？
```

这些问题必须回到代码里找。

所以我做了一个小工具：**Project Xray / 项目 X 光机**。

它的原则很简单：

> 先有代码证据，再有问题和答案。

### 它怎么工作

1. 静态扫描 Java / Spring Boot 项目
2. 找到疑似问题信号，例如循环查库、空 catch、事务里调 RPC、硬编码密钥、缓存未失效
3. 生成 IDE 风格代码截图
4. 输出带 `文件:行号` 的完整回答
5. 给出追问和修改建议
6. 校验报告，确保每道题都有证据

举个例子。

项目里有一段循环查库：

```java
for (Long id : ids) {
    orderMapper.selectById(id);
}
```

工具会生成一张代码截图，并给出：

```text
Q1. 这个订单处理循环为什么逐条查询？

30 秒回答：
项目当前是在循环内逐条调用 selectById。如果订单量不大，这样写最简单；
但数据量增长后会产生 N+1 查询，所以我会优先改成批量查询或一次 join。

追问：
如果 ID 列表很大，批量查询怎么做？
完整回答：
可以按固定大小分批查询，再在内存中按原顺序组装结果，
避免单条 SQL 参数过多。
```

它不是只告诉你“有 N+1”，而是让你知道：

- 问题在哪一行
- 面试时怎么说
- 追问答什么
- 怎么改
- 需要补什么基础

### 它不做什么

- 不执行你的项目代码
- 不安装你的项目依赖
- 不上传源码
- 不编造线上 QPS、用户量、故障次数
- 不把“通用八股”伪装成你项目里的事实
- 不假装改后代码是项目原有实现

### 适合谁

- 正在准备 Java 后端项目面试
- 简历里写了 Spring Boot / MyBatis / Redis / JWT
- 刚做完课程设计，但说不清项目结构
- 想从自己的代码出发学，而不是背通用题
- 正在摸黑学 Java，希望有人从代码里带你走一遍

### 怎么试

4. 哪个代码截图不清楚？
5. 你希望增加哪个 Java / Spring Boot 场景？

如果你也正在摸黑学 Java，欢迎拿自己的项目试一次。  
如果它确实帮你少卡住一次，再点 Star 也不迟。

## V2EX 短版

标题：

> 做了个 Java 项目 X 光机：把项目代码变成面试官会追问的问题

正文：

最近在准备 Java 后端项目面试，发现一个很尴尬的问题：项目是我写的，但很多地方说不清为什么这么写。

市面上的面试题工具大多给通用八股。但面试官真正会问的是：

- 你这个循环为什么逐条查库？
- catch 住异常之后调用方怎么知道失败？
- 你说用了 Redis，为什么不用本地缓存？
- 事务为什么放在这一层？

所以我做了个静态扫描工具，先找代码证据，再生成带 `文件:行号` 和代码截图的问题。

它不是让 AI 凭空编题，而是：

1. 扫描 Java/Spring Boot 项目
2. 找出循环查库、空 catch、事务内 RPC、硬编码密钥等信号
3. 生成 IDE 风格代码截图
4. 输出 30 秒回答、完整解释、追问和修改建议
5. 校验每条结论是否有证据

仓库：  
https://github.com/Deng-deng-liu/skill

目前只支持 Java/Spring Boot，还是 beta。  
如果你也在准备项目面试，欢迎拿自己的项目试一下，尤其欢迎告诉我误报和看不懂的答案。

## 发布建议

### 掘金

- 标签：Java、Spring Boot、面试、开源、后端
- 封面：一张“代码截图 + 问题 + 30 秒回答”的拼图
- 文中至少放 2 张真实代码证据图
- 结尾不要只放 GitHub 链接，要明确邀请反馈

### V2EX

- 发在“程序员”或“分享创造”节点
- 标题不要太营销，突出“我做了个什么”
- 正文短一点，把问题、做法、限制和链接说清楚
- 主动说明当前只支持 Java/Spring Boot，避免预期错位

### 发布后

- 前 24 小时尽量回复评论
- 把真实反馈整理成 Issue
- 一周内发一次“根据反馈修了什么”的更新
- 不要刷星，不要群发广告
